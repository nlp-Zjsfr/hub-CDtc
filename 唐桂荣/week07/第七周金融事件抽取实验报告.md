# 金融公告事件抽取实验报告

RoBERTa 与生成式模型对比

第七周作业    实验日期 2026年11月26日

## 摘要

本次作业复用课程金融公告数据，完成 RoBERTa 联合抽取、类型条件流水线、本地 Qwen3 0.6B Base 提示抽取及 DeepSeek 官方 API 抽取。将八种配置统一到相同的60条开发集样本后，DeepSeek few-shot 的论元 F1 最高，为59.06%；RoBERTa pipeline 的完整事件 F1 最高，为11.21%。这两个指标反映不同能力，需结合触发词边界、论元集合和标注口径解释。

## 1 任务与数据

任务是从一句金融公告中抽取一个事件，输出事件类型、触发词及各角色的论元文本。数据使用课程处理后的 DuEE-Fin 句子级版本，覆盖13类事件、61种去重角色，共92个类型与角色槽位。此次范围不包含 BiLSTM 与 LoRA 微调。

**表1 数据规模与用途**

| 数据文件 | 样本数 | 用途 |
| --- | --- | --- |
| train_extract.jsonl | 5747 | 联合抽取 类型分类 专家训练 |
| dev_extract.jsonl | 930 | 全量开发集评测 |
| train_detect.jsonl | 32794 | 事件有无检测训练 |
| dev_detect.jsonl | 5302 | 事件有无检测评测 |
| 固定开发集子集 | 60 | 八种配置统一比较 |

60条样本的选取规则为先按 id 和 sent_id 排序，再用 Random(42) 打乱并取前60条。所有方法按同一组样本编号重算指标；该子集包含60个金标事件和263个金标论元。

### 评价指标

精确率 P 衡量预测中正确的比例，召回率 R 衡量金标中被找回的比例，F1 为两者的调和平均值。TP、FP、FN 分别表示正确预测、多抽和漏抽。

```text
P  = TP / (TP + FP)
R  = TP / (TP + FN)
F1 = 2 × P × R / (P + R)
```

触发词按事件类型和文本精确匹配；论元在同类型事件对齐后，按角色与文本组成的多重集合比较。完整事件要求类型、触发词及全部论元集合同时匹配。预测失败的样本保留为漏抽，不缩小评测分母。

## 2 方法与实验设置

### 2.1 RoBERTa 联合抽取

使用本地 roberta_base 预训练权重。该中文 RoBERTa 的配置采用 BERT 兼容架构，由 AutoModel 按配置加载完整12层编码器。将文本拆为字符后分词，通过 word_ids 对齐字符与 token；每个字符仅首个子词参与监督，特殊位置与其余子词标签为忽略值。

联合标签体系将触发词按13类事件区分，61个角色跨类型共享，BIO 标签总数为149。分别使用 Linear 与 CRF 解码头；硬约束版本复用训练好的 CRF 权重，仅在解码阶段约束 BIO 起始与转移。

联合模型训练3轮，最大长度256，batch为4，梯度累积8；编码器学习率为2e-5，头部学习率为1e-4，优化器为 AdamW。从5747条 train 中划出574条内层验证数据，实际拟合5173条；依据内层验证指标选择 epoch，最终选中第3轮。

### 2.2 类型条件流水线

流程为事件检测、13类事件分类、类型条件论元抽取。前两阶段使用完整12层编码器；每种事件类型训练一个前4层编码器加 Linear 头的专家，共1个检测器、1个类型分类器及13个专家，合计15个模型。各专家标签空间为11至21类。

检测器和类型分类器各训练2轮，最大长度192，batch为4、梯度累积16、学习率2e-5。最终专家训练3轮，最大长度256，batch为4、梯度累积1、学习率3e-5。分类和专家训练使用对应的完整 train，采用预设轮数。

### 2.3 本地与 API 生成式抽取

本地使用 Qwen3-0.6B-Base，不进行微调。采用关闭思考的聊天模板、贪心解码、左侧填充，MPS 上以 FP16 和 batch 1 推理。提示词上限4096 tokens，生成上限384 tokens；生成期间每32个 token 及每批结束时回收未使用的 MPS 缓存。

API 使用 DeepSeek 官方地址，模型标识为 deepseek-flash，对应实验当日的 V4.1 Flash 服务。请求关闭思考，temperature 为0，启用 JSON 对象模式，输出上限1024 tokens；保存请求参数、响应模型标识、原始回复与用量。

zero-shot 提供 schema、任务说明和输出格式；few-shot 另加入六条 train 示例。示例覆盖解除质押、质押、股东减持、股东增持、高管变动和企业收购，已逐条核对训练样本编号与金标；原课程两条不在当前 train 中的示例已替换为同类型训练样本。

### 2.4 环境与比较范围

本地实验环境为 macOS arm64、Python 3.11.15、PyTorch 2.13.0 和 Transformers 5.18.0，计算设备为 Apple MPS。此次比较的是完整工程方案：训练数据划分、模型规模、生成预算及格式约束均有差异，不能将全部分差归因于单一因素。

## 3 实验结果与比较

表2统一使用相同的60条 dev 样本。RoBERTa 各版本由已保存的全量预测筛选同一子集后，交给公共评测器重新计分；没有将60条与930条的指标混排。所有数值均为百分比。

**表2 同批60条开发集上的 F1**

| 方法 | 触发词 F1 | 论元 F1 | 完整事件 F1 |
| --- | --- | --- | --- |
| RoBERTa Linear | 61.95 | 29.92 | 3.54 |
| RoBERTa CRF | 63.06 | 34.17 | 3.60 |
| RoBERTa CRF＋硬约束 | 63.64 | 35.70 | 3.64 |
| RoBERTa pipeline | 80.37 | 46.50 | **11.21** |
| Qwen Base zero-shot | 30.19 | 7.86 | 0.00 |
| Qwen Base few-shot | 55.00 | 23.27 | 1.67 |
| DeepSeek zero-shot | **83.76** | 54.69 | 3.42 |
| DeepSeek few-shot | 83.05 | **59.06** | 5.08 |

### 论元抽取结果

DeepSeek few-shot 的论元 F1 为59.06%，比其 zero-shot 的54.69%高4.37个百分点，比 pipeline 的46.50%高12.56个百分点。加入示例后，正确论元从140个增至145个，多抽从109个降至83个，漏抽从123个降至118个；改善主要体现在减少多抽。

### 触发词与完整事件结果

DeepSeek zero-shot 的触发词 F1 为83.76%，高于 few-shot 的83.05%；因此，加入示例并未使所有指标同时上升。Pipeline 的完整事件 F1 为11.21%，对应6个完全匹配事件；DeepSeek few-shot 为5.08%，对应3个。完整事件要求整组字段一致，部分论元的改善不一定转化为更多完全匹配。

### 本地小模型结果

Qwen Base 的 few-shot 论元 F1 从7.86%升至23.27%，触发词 F1 从30.19%升至55.00%，表明示例在本次配置下有效。但它仍低于已微调的 RoBERTa 与云端 API 方案；该结果仅描述 Base 版本，不能套用于同规模的指令模型或经过 SFT 的模型。

本次仅使用一个固定的60条子集，未做重复采样或统计显著性检验。表中排名是该样本与配置下的描述性结果。

### 3.2 全量结果与训练诊断

表4仅记录930条完整 dev 上的 RoBERTa 结果，用于检查训练与解码改动。该表不包含只评测60条的生成式模型。

**表4 全量930条开发集上的 F1**

| 方法 | 触发词 F1 | 论元 F1 | 完整事件 F1 |
| --- | --- | --- | --- |
| RoBERTa Linear | 61.09 | 31.87 | 4.39 |
| RoBERTa CRF | 65.45 | 34.09 | 5.52 |
| RoBERTa CRF＋硬约束 | 62.43 | 37.06 | 5.76 |
| RoBERTa pipeline | 75.90 | 47.40 | 12.17 |

硬约束解码使 CRF 论元 F1 从34.09%升至37.06%，触发词 F1 则从65.45%降至62.43%。约束减少非法序列，并不保证每个任务指标都上升。最终 pipeline 论元 F1 为47.40%，完整事件 F1 为12.17%。

**表5 全量930条上的 BIO 非法序列统计**

| 配置 | 字符序列含非法比例 | token序列含非法比例 |
| --- | --- | --- |
| Linear | 87.85% | 未单独记录 |
| CRF 常规解码 | 85.91% | 未单独记录 |
| CRF 硬约束解码 | 6.13% | 0.00% |

硬约束施加于 token 解码；字符还原后的非法率仍为6.13%，因此两个层级应分别报告，不能将 token 级的0直接表述为字符级也完全合法。

### 专家训练不足的修正

最初专家采用 batch 4、梯度累积8和3轮训练，少数类型实际更新很少，模型主要输出 O，整条流水线抽取 F1 曾为0。将专家梯度累积改为1后，复用检测器和类型分类器，重新训练全部专家。

**表6 相同3轮下专家的参数更新次数**

| 专家 | 旧版 累积8 | 新版 累积1 |
| --- | --- | --- |
| 被约谈 | 6 | 42 |
| 中标 | 69 | 531 |
| 股份回购 | 93 | 735 |

专家重训耗时1000.2秒，约16.7分钟，仅指13个专家，不包含此前分类器训练。开发阶段曾根据 dev 异常修正配置，因此本文统一称开发集实验，不将这些结果当作封存独立测试集上的最终泛化估计。

## 4 错误分析与结论

### 4.1 金标覆盖差异

原句为“斯尔克2019年亏损432.85万元 较上年同期由盈转亏”。三种输出均判断为亏损事件，触发词均为“亏损”。差异在于金标只标了公司名称和亏损变化，API 另抽出财报周期与净亏损。

**表7 案例一的论元比较**

| 角色 | 金标 | DeepSeek few-shot | Pipeline |
| --- | --- | --- | --- |
| 公司名称 | 斯尔克 | 斯尔克 | 斯尔克 |
| 亏损变化 | 由盈转亏 | 由盈转亏 | 由盈转亏 |
| 财报周期 | 未标注 | 2019年 | 未输出 |
| 净亏损 | 未标注 | 432.85万元 | 未输出 |

按当前评测口径，API 的两项额外论元都算 FP，完整事件也不匹配；pipeline 与金标完全一致。从原文语义看，这两项额外信息有明确文本依据。该例说明，与金标不同的预测需要进一步核查，不能全部归为模型编造，也不能据此直接判定整份金标质量。

### 4.2 流水线漏抽

原句为“大众汽车将投资至多5亿欧元升级斯洛伐克工厂”。金标将其归为企业融资，触发词为“投资”。DeepSeek few-shot 的类型、触发词和全部论元均匹配；pipeline 最终输出为空。

**表8 案例二中金标与 API 一致的论元**

| 角色 | 金标与 DeepSeek few-shot |
| --- | --- |
| 投资方 | 大众汽车 |
| 融资金额 | 至多5亿欧元 |
| 被投资方 | 斯洛伐克工厂 |

该句体现了流水线最终漏抽与 API 完整抽取的差别。仅凭最终空结果，不能确定错误来自检测器、类型分类器还是专家的触发词预测；需要阶段输出才能进一步定位。

### 4.3 触发词边界差异

原句节选为“比速科技(01372)：汽车发动机业务客户北汽银翔的破产申请已被提交”。正文还给出了2019年9月10日和完整公司名称。金标与 API 都识别为企业破产，但触发词的截取范围不同。

**表9 案例三的关键字段**

| 字段 | 金标 | DeepSeek few-shot |
| --- | --- | --- |
| 事件类型 | 企业破产 | 企业破产 |
| 触发词 | 破产 | 破产申请 |
| 破产公司 | 北汽银翔企业有限公司 | 北汽银翔企业有限公司 |
| 破产时间 | 2019年9月10日 | 2019年9月10日 |

API 的两项论元均正确，触发词多包含“申请”两个字，因此触发词和完整事件按精确匹配都不正确。该例也解释了为什么论元可以得分，而完整事件不得分：公共评测器在同类型事件下比较论元，不要求触发词先精确匹配。

### 4.4 实验结论

在同一批60条开发集上，DeepSeek few-shot 的论元 F1 为59.06%，是本次八种配置中最高；DeepSeek zero-shot 的触发词 F1 最高，为83.76%。Pipeline 的完整事件 F1 最高，为11.21%。报告应分别讨论各指标，结论限定于本次样本与配置。

六条训练示例同时改善了本地 Base 模型和 API 的论元抽取表现，但 API 的触发词指标略降。JSON 模式解决了本次 API 回复的格式问题，仍不能保证角色、边界和全部论元集合与金标一致。

### 4.5 局限与后续改进

样本仅60条，尚不足以代表全部事件类型和长尾角色；后续可在另行保留的评测数据或全量数据上验证，并做多次采样与置信区间分析。完整930条 dev 与60条主表应继续分开报告。

不同方案的训练数据量、模型规模、输出长度、JSON 约束及运行环境不同；本报告属于工程方案比较，不能视作严格控制变量的模型能力消融。开发集参与过排错，后续还需要独立测试集。

针对错误可先统一触发词与论元的边界规范，人工复核一批金标覆盖差异，再分别分析流水线各阶段漏失。对于 Qwen，应另做输出长度控制实验，区分回复预算与模型能力的影响。本次未开展 LoRA，不据此推断微调后的表现。
